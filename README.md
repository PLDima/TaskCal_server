# TaskCal backend

REST API for the TaskCal Android app: it stores the user's tasks, task completions, food entries and
profile.

**Stack:** Ktor 3 · Exposed 1.x · PostgreSQL · Flyway · HikariCP · kotlinx.serialization.
Tests run on H2 in PostgreSQL mode, so they don't need a database server.

## Auth (v1)

The app generates a random **device token** (32–256 characters, e.g. two UUIDs) on install and
keeps it on the phone, backed up with the app data.

1. `POST /api/v1/auth/device` `{"deviceToken": "..."}` registers it. The call is idempotent and
   returns `{"userId": "..."}`.
2. Every other call sends `Authorization: Bearer <deviceToken>`.

Only a SHA-256 hash of the token is stored, in `auth_identities` under provider `device`. Users and
their credentials live in separate tables, so Google login can be added later as another provider
on the same user, with no data migration.

## API (`/api/v1`)

| Endpoint | |
|---|---|
| `POST /auth/device` | Register a device token (no auth) |
| `GET /me` · `DELETE /me` | Get the current user; delete the account and all its data |
| `GET /me/profile` · `PUT /me/profile` | Profile and goals (`404` until first set) |
| `GET /tasks` · `GET/PUT/DELETE /tasks/{id}` | Tasks |
| `GET /tasks/{id}/completions` · `PUT/DELETE /tasks/{id}/completions/{cid}` | Completions of repeating tasks |
| `GET /food-entries?from=&to=` · `GET/PUT/DELETE /food-entries/{id}` | Food log |

IDs are UUIDs generated by the client, and `PUT` creates or replaces. Field and enum names match the
Android domain models. Date-times are zone-less ISO strings (`2026-11-09T07:30:00`). Errors are
`application/problem+json`. The full spec is served by Swagger UI at
`http://localhost:8080/swagger`; its source is `src/main/resources/openapi/documentation.yaml`.

`GET /health` is an unauthenticated liveness check.

## Running locally

```bash
brew install postgresql@17
brew services start postgresql@17
/opt/homebrew/opt/postgresql@17/bin/createdb taskcal

./gradlew run          # Flyway migrates the schema on startup
./gradlew test         # no database needed
```

Configuration (`src/main/resources/application.yaml`) reads these environment variables:

| Variable | Default |
|---|---|
| `DB_URL` | `jdbc:postgresql://localhost:5432/taskcal` |
| `DB_USER` / `DB_PASSWORD` | empty: the OS user, which is Homebrew's default role |
| `PORT` | `8080` |

Schema changes go in a new `src/main/resources/db/migration/V<n>__<name>.sql`. Never edit a
migration that has already been applied.

## Layout (`inc.dimasic.taskcal.backend`)

```
Application.kt   wiring: database → repositories → services → plugins → routes
api/route/       HTTP routes          api/dto/   wire format + mappers
domain/service/  rules & ownership    domain/model/
data/repository/ Exposed queries      data/table/   data/DatabaseFactory.kt
plugins/         serialization, auth, status pages, call logging
```
